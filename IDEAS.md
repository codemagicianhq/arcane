Arcane is published on GitHub, uses GitHub PRs, and `spell-bug` and `spell-create-pull-request` already speak GitHub natively - the tracking model is the only layer that does not. <!-- status: new -->
- **[2026-08-01 19:22]** [#attribution] Split the `Agent` trailer into runtime versus persona: `Agent` = the runtime that executed (`copilot`, `claude`), `Persona` = the roster identity it operated as when applicable, `Role` = derived from that persona's roster entry and never typed by hand, plus `Model-Source` to mark self-reported values. Prerequisite: `.arcane/agents.yaml` must exist - it does not today, which is why persona attribution is unavailable and why EF-28 downgrades merge to human. Composes with EF-27's roster validation. <!-- status: new -->
- **[2026-08-02 01:25]** [#deduplication] Deduplication must diff before deleting. During housekeeping, compare duplicated blocks and merge any unique content before removing either copy; "duplicate" usually means drifted copies, not identical copies. <!-- status: new -->
- **[2026-08-02 02:05]** [#spell-compiler] Spell compiler, not spell runtime: the CLI should resolve and emit spells, not execute them. `spell render <name>` prints a fully resolved prompt to stdout and the agent client runs it, so `/spell-*` becomes a thin shim. This is EF-24's architecture-level answer: anything the CLI can compute stops being a rule an agent can get wrong. Render-time injection of `.arcane.json` config, governance paths, `BUSINESS_ROOT`/`SUBJECT_ROOT`, remote-state classification, and EF-27 validated roster identity would structurally defuse EF-02, EF-08, EF-14, EF-19, EF-23, EF-29, and fabricated author/model trailers. Explicitly not a runtime with API keys and conversations, because that means becoming the coding session. Key unresolved tension: `spell-authoring-standards` D2 Gold requires spells to work in a vanilla repo with no Arcane files present, and CLI-rendered spells may break that, so render/fallback needs a decision. Other risks: two sources of truth, CLI-vs-asset version skew, and migrating 33 client shims. <!-- status: new -->
