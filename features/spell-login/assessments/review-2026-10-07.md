## Findings

### Medium severity

- **R1 — Query-free result route and security headers remain required before serving the Gate pages.** The current callback displays its plain result on the URL carrying the OAuth authorization code, and the response only sets `Content-Type`. The separate `TODO.md` sign-in callback item calls for a query-free redirect, no-store/no-referrer/nosniff/CSP headers, a listener lifecycle through the result request, replay tests, and a browser visual review. This is preexisting behavior and does not block this validation/storage fix, but it blocks vendoring the new visual page into the CLI.

## Architecture Compliance

`browserLogin` still performs authorization-code plus PKCE on `127.0.0.1` with a random port and validates the provider response. `runLogin` now supplies the storage callback, so the page cannot claim success before `SessionStorage.save` completes. Device-code login saves after polling as before. The default browser launcher remains shell-free. Partial logout cleanup carries the media actually removed, reports the insecure file separately from the unavailable keychain, and retains a nonzero exit when keychain cleanup cannot be verified. The privacy-scan cleanup changes only documented organization references and distributed image-prompt text; the scanner was not weakened.
