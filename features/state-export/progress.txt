# Progress — the state export (spell state --json)

## Iteration 1 — SE-01 — 2026-11-04
### What was done
- src/assets/schemas/state.schema.json (draft 2020-12, $id https://arcaneai.net/schemas/state/v1, closed envelope, $defs per section, one example with ARC-031 names).
- src/modules/state/types.ts (TypeScript twin), src/modules/state/serialize.ts (STATE_SHAPE key-order table, canonicalize, serializeState, toPosixRelative).
- test/state-schema.test.ts: ajv validation, extra-key rejection, copy-assets ships the schema, devDependency-only check, shape-vs-schema order walk, sort/order tests.
### What was learned
- ajv strict mode rejects union `type` arrays unless `allowUnionTypes: true`; the schema keeps the unions (nullable fields) and the test passes the option.
- Under nodenext, import `{ Ajv2020 }` (named) from `ajv/dist/2020.js`; the default import is not constructable for tsc.
- scripts/copy-assets.ts copies all of src/assets/, so the schema ships with no script change; `npm pack --dry-run` lists it after a build.
- Sorting must use code-unit order, never localeCompare, for identical output across the CI matrix.
### What to watch for
- Books (todos/ideas/done) export as `{ open, done, items[] }` per architecture D6, not as bare arrays as the PRD's ST-05 prose reads; the schema follows the architecture.
- `warnings[]` is sorted; every other array keeps collector order unless STATE_SHAPE names a sort key.

## Iteration 3 — SE-03 — 2026-11-04
### What was done
- src/modules/state/git.ts: collectGit(cwd, root, { runGit? }) -> { git | null, warnings }; remoteProvider, stripUserinfo, parseWorktreeList exported for tests.
- src/modules/git.ts: classifyGitCommand treats `worktree list` and `remote get-url` as reads (AMBIGUOUS_READ_FORMS); tests in git-execution-contract.test.ts.
- test/helpers/state-fixtures.ts: initRepo, commitFiles (pinned dates), repoWithOneCommit, withUpstream (bare upstream on disk, ahead/behind, optional origin URL rewrite), addWorktree, detachHead.
### What was learned
- Absence is an answer, not a failure: no upstream / no remote / no trunk are null without a warning; only a timeout or unexpected error warns. The upstream probe (`rev-parse --abbrev-ref @{upstream}`) separates the two cases for ahead/behind.
- `uncommitted` reads `status --porcelain -uall` directly (same count as countUncommittedChanges) because that helper returns 0 on failure, which would report a timed-out read as a clean tree.
- `git remote` (no args) is still write-class by name; collectGit passes commandClass "read" for it. The origin check happens before `remote get-url` so a missing remote is silent.
- Worktree paths sort in code-unit order: "." comes before "../x".
### What to watch for
- The injected `runGit` in tests matches on args[0] (and args[1]); the real runner still runs for everything else, so each timeout test costs real git calls.

## Iteration 4 — SE-04 — 2026-11-04
### What was done
- src/modules/state/decisions.ts: parseDecisions (any `AA-NNN` prefix, CRLF-safe, title/status/date/anchor), parseAdrs + countAcceptedAdrsInWindow kept for Show Report, collectDecisions(root) sorted by id or null when absent.
- show-report/decisions-parser.ts removed; model.ts and show-report-parser.test.ts import from the new path (assertions unchanged).
- Drift fixed in its own commit: ARC-058 was missing from DECISIONS.md's table of contents (58 headings, 57 rows).
### What was learned
- GitHub heading anchors keep `_` (tracking_mode) and drop other punctuation; an em dash between spaces becomes `--`. The TOC-anchor parity test over the real DECISIONS.md is the guard.
- "Malformed entry" = a matching heading with neither a **Date:** nor a **Status:** line; it is skipped with a warning rather than exported half-empty.
### What to watch for
- `\d{3,}` ids sort by code unit; a four-digit id in a 3-digit series would sort before "ARC-100".
