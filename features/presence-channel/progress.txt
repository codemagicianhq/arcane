## Iteration 1 — PS-01 — 2026-11-05
### What was done
- src/modules/agent-ref.ts: createUuidV7Generator (injectable clock and random source), uuidv7,
  mintRef / mintAgentRef / mintTemplateRef / mintSessionRef, parseRef with an optional expected
  type, uuidV7Millis (tests and sorting only).
- test/agent-ref.test.ts: grammar, registry, 10,000-mint ordering, one-millisecond overflow,
  backwards clock, bit layout, twelve refusal reasons, import check.
### What was learned
- The 12-bit rand_a counter (RFC 9562 section 6.2 method 1) is seeded in its lower half
  (0..0x7ff) so a millisecond has at least 2,048 increments before the timestamp carries.
- The 48-bit timestamp is written with division, not shifts: JavaScript shifts are 32-bit.
- tsconfig has no noUncheckedIndexedAccess, so the typed lint rejects `!` on indexed reads.
### What to watch for
- parseRef's "expected type" reason reads "got one of type <type>"; the server's 404 for a
  non-session segment (PS-06) relies on parseRef(segment, "session").

### What was done
- src/assets/schemas/presence.schema.json: root = the session record; $defs capabilities, alias,
  agent, needsYou, remote, repository, checkout, harness, reportStatus, report, end, generator,
  health, snapshot, hello, event, error. Every object closed. D4 (patch) and D5 (record is the
  truth, event name is the reason) are in the descriptions.

  presenceCapabilities(), nullAgentBlock().

  example verbatim; record.v2.json carries the ARC-060 decision 13 block.
- test/helpers/presence.ts: schema compiler per $def, fixture loaders.
### What was learned
- The repository-wide secrets scan in `npm run build` (ARC-037) flags any upper-case identifier
  containing TOKEN followed by `=` or `:` and 8+ characters, in every file type. So: the env
  names live in PRESENCE_ENV with lowercase keys; tests must set the variable through a
  computed key (`{ [PRESENCE_ENV.token]: value }`), never `ARCANE_PRESENCE_TOKEN: "..."`; docs
  must not write `ARCANE_PRESENCE_TOKEN=<value>`.
- The schema is generated once by hand-run Python and then maintained as JSON; the twin test
  compares enums and keys, not the whole structure.
### What to watch for
- npm run build must be re-run before any built-CLI test (dist/ is stale otherwise).

## Iteration 3 — PS-03 — 2026-11-05
### What was done
- src/modules/presence/sessions.ts: createSessionTable({ now, mint, staleAfterMs?, expireAfterMs? })
  with report, end, get, snapshot, count, sweep and listen. Pure; returns copies.
- test/presence-sessions.test.ts: 25 tests over the key, the patch, the event precedence, both
  clocks, end, ordering and the import boundary.
### What was learned
- listen() (a set of listeners) instead of one onEvent option: the server needs to add and
  remove feeds, and tests need their own listener beside it.
- Expiry is checked before stale in sweep, so a record silent past both clocks emits only
  session.expired. An expired record carries stale: true in its last event.
### What to watch for
- report() trusts its input: validate.ts (PS-04) must run first. The table never sees a
  `done` status from a report.

## Iteration 4 — PS-04 — 2026-11-05
### What was done
- src/modules/presence/validate.ts: validateReport and validateEnd returning
  { ok, value } or { ok: false, code, field?, message }; oneLine(). Codes: invalid_field,
  unknown_field, missing_field, too_many_lines. Field paths are dotted (needs_you.3.action).
- test/presence-validate.test.ts: 32 tests.
### What was learned
- The Write tool turns a " " escape into the literal character. U+2028 is a line
  terminator inside a JavaScript regular-expression literal, so the regex broke the parse.
  Build such patterns with new RegExp("...") and a doubled backslash, and grep for literal
  U+2028 after writing.
- The agent block's ref, origin and revision are checked inline with the schema's patterns,
  because validate.ts may import nothing but ./types.js.
### What to watch for

## Iteration 5 — PS-05 — 2026-11-05

- vitest.config.ts: store.ts at the 95% critical tier.
### What was learned
- chmodSync is called unconditionally: on Windows it only touches the read-only bit, so there
  is no platform branch to leave uncovered, and restrictToCurrentUser is itself a POSIX no-op.
- A directory link is made with symlinkSync(target, path, "junction"), which works on Windows
  without privilege and is an ordinary symlink elsewhere.
### What to watch for

- store.ts imports session-store.ts (and so the keychain backend) for restrictToCurrentUser;

## Iteration 7 — PS-07 — 2026-11-05
### What was done
- test/presence-events.test.ts: 9 tests over the feed that PS-06's commit added to server.ts.
### What was learned
- Writes to every feed happen synchronously inside the table's listener, on one event loop,
  which is what keeps events ordered per session without any queue.
- Slot release on disconnect is asynchronous (the socket's close event); the test polls
  subscriberCount() for up to a second before opening the replacement feed.
### What to watch for
- serve (PS-08) must call closeFeeds() and server.closeAllConnections() before close(), or an
  open feed keeps the process alive.
