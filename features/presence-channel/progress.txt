### What was learned
- The 12-bit rand_a counter (RFC 9562 section 6.2 method 1) is seeded in its lower half
  (0..0x7ff) so a millisecond has at least 2,048 increments before the timestamp carries.
- The 48-bit timestamp is written with division, not shifts: JavaScript shifts are 32-bit.
- tsconfig has no noUncheckedIndexedAccess, so the typed lint rejects `!` on indexed reads.
### What to watch for
- parseRef's "expected type" reason reads "got one of type <type>"; the server's 404 for a
  non-session segment (PS-06) relies on parseRef(segment, "session").

### What was learned
- The repository-wide secrets scan in `npm run build` (ARC-037) flags any upper-case identifier
  containing TOKEN followed by `=` or `:` and 8+ characters, in every file type. So: the env
  names live in PRESENCE_ENV with lowercase keys; tests must set the variable through a
  computed key (`{ [PRESENCE_ENV.token]: value }`), never `ARCANE_PRESENCE_TOKEN: "..."`; docs
  must not write `ARCANE_PRESENCE_TOKEN=<value>`.
- The schema is generated once by hand-run Python and then maintained as JSON; the twin test
  compares enums and keys, not the whole structure.
### What to watch for
