## Claim

Arcane can install framework files and create a new venture, but it has no workflow for bringing an existing document tree under Arcane governance.

## Verification

Confirmed as a feature gap. Current profiles are limited to full, lite, methodology, and governance-only at [profiles.ts](../../../src/config/profiles.ts#L24-L67). `spell-bootstrap-business` creates a new business folder and overview at [spell-bootstrap-business.prompt.md](../../../src/assets/.github/prompts/spell-bootstrap-business.prompt.md#L32-L45). The 33 registered prompts at [registry.ts](../../../src/modules/registry.ts#L97-L143) contain no adoption spell or existing-tree inventory workflow.

## Impact

Operators must invent structure discovery, classification, migration, and governance backfill for existing repositories. The cost grows with the size and sensitivity of the tree.

## Proposed fix

Route this item into the unified docs-mode PRD with EF-04, EF-07, EF-10, EF-11, EF-12, EF-17, and EF-19. Do not design or ship adoption as an isolated spell.

A complete `spell-adopt-docs.prompt.md` draft already exists, was written against `spell-authoring-standards`, and is referenced by the docs-mode PRD as MH-04. Treat that draft as an implementation input to request from the maintainer, not as a workflow to re-derive from this report.

## Open questions

Does the supplied MH-04 draft fully align with the final profile, subject-root, sensitive-content, Git-safety, and local-only lifecycle decisions made by the unified PRD? Any delta should be reviewed against the draft rather than replacing it.
