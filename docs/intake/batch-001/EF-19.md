## Claim

`spell-close-session` requires a topic branch, Azure DevOps PR lifecycle, `origin`, and `main`, so its otherwise useful continuity workflow cannot complete unchanged in a repository with no remote.

## Verification

Confirmed. Steps 9 and 10 require branch creation, an ADO PR, and `git checkout main && git pull origin main` at [spell-close-session.prompt.md](../../../src/assets/.github/prompts/spell-close-session.prompt.md#L103-L127). The PR-readiness table also directs docs-only branches to a PR at [spell-close-session.prompt.md](../../../src/assets/.github/prompts/spell-close-session.prompt.md#L159-L168). This contradicts the shipped docs-only governance rule permitting local fast-forward merges at [cicd-standards.md](../../../src/assets/.arcane/governance/cicd-standards.md#L49-L52).

## Impact

Local-only repositories cannot close sessions without overriding the spell. The failure occurs after continuity documents have been edited, increasing the chance of a half-finished close.

## Proposed fix

In the docs-mode PRD, detect remote capability before the commit/PR phase and define a local trunk path that skips PR and pull operations while preserving an explicit branch/merge policy. Reconcile that path with the unshipped ADR citation tracked by EF-23.

## Open questions

Should a local-only repository commit directly on its trunk or use a local topic branch and fast-forward merge? How should repositories with a remote but no supported PR provider behave?
