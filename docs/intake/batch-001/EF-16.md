## Claim

`spell-commit-work` groups changes by topic before determining authorship, so a mixed-author batch can be committed under one incorrect author without an error.

## Verification

Confirmed. Step 3 groups and splits work only by concern in [spell-commit-work.prompt.md](../../../src/assets/.github/prompts/spell-commit-work.prompt.md#L42-L52). Step 4 then selects one human or agent identity for the resulting batch at [spell-commit-work.prompt.md](../../../src/assets/.github/prompts/spell-commit-work.prompt.md#L55-L62), and step 8 executes one `git commit --author="..."` for the staged files at [spell-commit-work.prompt.md](../../../src/assets/.github/prompts/spell-commit-work.prompt.md#L112-L116). No instruction sends a mixed-author batch back for repartitioning.

## Impact

Any commit containing work from multiple authors can silently record the wrong authorship. Git accepts the commit, so the audit-history defect has no failure signal and is especially material in evidentiary repositories.

## Proposed fix

Determine authorship before topic grouping. Partition changed files by author first, then group by concern within each author partition. State the invariant explicitly: one commit has exactly one author; changes spanning authors must be split.

## Open questions

None. The ordering and invariant are mechanical; vendor authorship remains a separate policy decision in EF-15.
