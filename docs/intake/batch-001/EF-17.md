## Claim

The Arcane framework repository and consuming docs repositories need a repository-owned line-ending baseline. Without one, Git installation defaults can create whole-file phantom diffs that destroy review signal.

## Verification

Confirmed in the framework repository. Before remediation, no root `.gitattributes` existed and system Git configuration supplied `core.autocrlf=true`. `git ls-files --eol` reported 224 tracked files as `i/lf w/crlf`. The operator independently observed 224 modified paths in ordinary diff/status output, while `--ignore-cr-at-eol` reduced the real tracked content change to one added consumed-handoff marker. That is a review signal-to-noise ratio of 1:224 in the repository where the accepted fixes will land.

The canonical registry also installs no `.gitattributes` into consuming repositories at [registry.ts](../../../src/modules/registry.ts#L13-L182), so the docs-mode requirement remains valid even though this item is now routed as a shipped-framework bug.

The review-noise failure has since surfaced in three separate workflows. On 2026-08-02, the drift spell initially treated 38 byte-different root/canonical pairs as meaningful drift even though operator verification found only 6 real content differences; 32 were line-ending-only. A separate check two days earlier similarly reported 23 differences when only 6 were substantive. The drift spell now requires a byte comparison followed by line-ending-normalized comparison and reports real content drift separately from line-ending-only drift.

## Impact

Normalization-only diffs can hide meaningful changes during review, including changes to data-preservation, attribution, and approval controls. This is review-integrity damage in the framework itself, not only a future docs-profile feature.

## Proposed fix

The immediate framework mitigation was applied first in dedicated commit `9946096`: add `* text=auto eol=lf` followed by PNG/GIF binary overrides, then run `git add --renormalize` while excluding the one real uncommitted content edit. The index already stored LF, so the dedicated commit correctly touched only `.gitattributes`. Lint and all 341 tests passed with one skipped.

Complete the bug fix by adding regression coverage for Windows/system `core.autocrlf=true`, verifying text resolves to `eol=lf`, binary assets resolve to `text: unset`, and ordinary review output contains only real content changes. Retain the consuming-repository requirement in the unified docs-mode PRD: emit the same baseline ahead of EF-10 binary overrides and test it on Windows and Linux fixtures.

## Open questions

Should `spell update` ever add a baseline to an existing consuming repository automatically, or only report the migration because renormalization can produce a large intentional diff? How should the CLI distinguish a repository with an intentional existing EOL policy from one with no policy?
