## Claim

`spell init` leaves no baseline commit or guaranteed `main` branch, while `spell-close-session` requires branch and remote operations that assume both exist.

## Verification

Confirmed, with one important correction: the submitted premise that `spell init` runs `git init` is false. Current `runInit` only probes Git status through [init.ts](../../../src/commands/init.ts#L138-L157), writes files and the manifest, and prints manual next steps at [init.ts](../../../src/commands/init.ts#L272-L318). It neither initializes Git nor creates a commit.

`spell-close-session` then requires a topic branch, commit, PR, and return to `main` at [spell-close-session.prompt.md](../../../src/assets/.github/prompts/spell-close-session.prompt.md#L103-L127). In a new folder this can fail earlier than reported because there may be no repository at all; in an existing unborn repository there is no baseline branch to return to.

## Impact

The first session lifecycle is not self-consistent after installation. The operator must invent Git initialization, branch naming, initial attribution, and the first commit before Arcane's own close workflow can run.

## Proposed fix

Define the initialization contract together with EF-15: either create a baseline `main` commit during interactive init, or make close-session explicitly handle non-Git and unborn-repository states. Do not silently commit when `spell init` is used to add Arcane to an existing repository.

**Root cause confirmed:** a default Git for Windows install sets `init.defaultBranch=master` at the system config level (`C:/Program Files/Git/etc/gitconfig`). `spell init` never chooses `master` itself — the operator's `git init`/first commit does, because nothing overrides the system default. "Create a baseline `main` commit during interactive init" is therefore not sufficient as written: on most Windows installs, an unqualified `git init` + first commit lands on `master`, silently reproducing this exact bug under a fix meant to close it. The fix must explicitly create or rename the branch to the intended default (e.g. `git init -b main` or `git branch -m main` immediately after the first commit) rather than assume `main` exists because Arcane's own docs say it should.

## Open questions

Should automatic Git initialization and scaffold commit be opt-in, limited to empty directories, or a separate explicit command?
