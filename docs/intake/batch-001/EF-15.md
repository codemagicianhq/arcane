## Claim

The attribution model distinguishes human and agent output but does not define authorship for Arcane's vendored scaffold.

## Verification

Confirmed. Step 4 of [spell-commit-work.prompt.md](../../../src/assets/.github/prompts/spell-commit-work.prompt.md#L55-L62) offers only human and AI/tool branches. The full profile installs every registered component through [profiles.ts](../../../src/config/profiles.ts#L24-L30), including governance, prompts, templates, and continuity files, but no source defines a vendor author or vendor task type.

## Impact

Every first scaffold commit requires an undocumented attribution judgment. Human authorship overstates creation; attributing copied framework files to the executing agent confuses execution with authorship.

## Proposed fix

Decide whether vendored content uses an Arcane identity, the human committer with a vendor trailer, or no author override plus provenance metadata. Apply that policy consistently to initial install and later managed-file updates.

## Open questions

Should provenance identify the package version rather than an email identity? How should a commit mixing vendor updates with operator customizations be partitioned under EF-16?
