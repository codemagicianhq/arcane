## Claim

The full scaffold does not create `README.md` or `project.md`, although orientation and planning spells read them immediately.

## Verification

Confirmed. The session-continuity component contains only `TODO.md`, `DECISIONS.md`, `ai-context/system-prompt-context.md`, and `journal/.gitkeep` at [registry.ts](../../../src/modules/registry.ts#L168-L182). `spell-open-session` reads both missing files at [spell-open-session.prompt.md](../../../src/assets/.github/prompts/spell-open-session.prompt.md#L21-L25), with graceful fallback rather than creation.

The submitted occurrence counts do not reproduce exactly. Current canonical prompts contain 8 matching README lines across 5 files and 15 matching `project.md` lines across 12 files. The defect is real, but the batch's `6` and `12` figures use an inconsistent counting basis.

## Impact

New repositories begin without a canonical project identity or navigation surface. Spells can continue, but they must infer context or ask repeatedly, reducing the value of session continuity from day one.

## Proposed fix

Resolve EF-02 first. Under a root-owned document model, add install-once draft stubs for `README.md` and `project.md`. Under a vendored-template model, install templates and explicitly create operator-owned instances during onboarding.

## Open questions

What minimum project identity belongs in the stub, and should non-empty existing repositories ever receive a generated README?
