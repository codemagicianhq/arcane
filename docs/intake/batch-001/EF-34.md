## Claim

Git exports repository-context environment variables (`GIT_DIR`, and situationally `GIT_INDEX_FILE`, `GIT_WORK_TREE`, `GIT_PREFIX`) to hook subprocesses. This repository's pre-commit hook runs the full vitest suite, and several test fixtures create throwaway repositories that they drive by spawning `git` with only `cwd` pointing at the fixture directory. Inherited `GIT_DIR` overrides `cwd` resolution, so fixture `git init` / `commit` / `config` calls operate on the real repository instead of the fixture: fixture commits land on the real checked-out branch, and fixture configuration writes land in the shared physical `.git/config` — which every linked worktree shares, making config damage fleet-wide.

## Verification

Three confirmed firings. (1)–(2) 2026-08-03 ([journal](../../../journal/2026-08-03-batch-001-queue-closeout-and-worktree-mount-near-miss.md)): the class fired twice in one session — `core.bare` flipped to `true`, Git identity overwritten, stray `test: seed …` fixture commits left on real branches. Repaired in-session and documented with a `--no-verify` workaround, but never filed as a finding or queued for a root-cause fix. (3) 2026-08-15: a docs-only commit (the ARC-028 draft) run from linked worktree `arcane-arc028` triggered the hook suite; three fixture commits (`test: seed line ending fixture`, `test: seed baseline`, `test: seed update baseline`) landed on the real session branch — the first silently swept the session's staged real changes into itself — while the shared config was flipped to `core.bare=true` with identity `Arcane Tests <arcane-tests@example.invalid>`, breaking the primary checkout for a concurrent live session (`fatal: this operation must be run in a work tree`). The contaminated branch was pushed before detection and corrected with `--force-with-lease`. Contaminated commits preserved on `backup/arc028-contaminated-2026-08-15`.

**Additional instance found 2026-08-31 (BC-03 branch-hygiene sweep), not previously logged here:** `sessions/2026-08-02-provider-neutral-close`'s sole unlanded commit is `test: seed main` — the exact fixture-seeding message `test/version-bump-gate.test.ts`'s own git helper writes — carrying a snapshot of unrelated in-progress work (package.json/package-lock.json/spell-close-session.prompt.md/a new test file) that a leaking fixture run committed to this real branch instead of an isolated temp directory. Confirmed contamination, not real authored work: the "new" test file in that diff (`test/prompt-session-branch-gate.test.ts`) already exists on `main` today via legitimate history. No repair was needed (the branch was never merged), but it is additional evidence of the same defect this file documents, alongside the five already-quarantined `backup/*` branches. Queued for the operator's abandon call at [OPERATOR-QUEUE.md Q-003](../../../docs/plans/become-current/OPERATOR-QUEUE.md#q-003--four-content-holding-local-branches-land-or-abandon) rather than deleted unilaterally, since it still technically holds content not on `main`.

## Impact

Any commit that runs the hook can corrupt branch history and fleet-wide repository configuration, including checkouts belonging to concurrent sessions that ran nothing at all. The only existing mitigation is a journal-documented `--no-verify` workaround — which trains operators and agents to bypass hooks as routine practice, eroding the very control the hook exists to provide. Per [ARC-023](../../../DECISIONS.md#arc-023--normative-controls-require-inline-enforcement-contracts) (normative controls require inline enforcement contracts) and [ARC-024](../../../DECISIONS.md#arc-024--confirmed-severity-must-have-operational-consequences) (confirmed severity must have operational consequences), a thrice-confirmed high-severity defect whose remediation is a narrative workaround is an inert control. ARC-028's R7 hazard rail names shared-`.git` state as fleet-wide but is behavioral policy; it does not remove this leak.

## Proposed fix

Operator-approved scope (2026-08-15): (a) sanitize the environment in the test git helpers — strip all `GIT_*` variables before spawning `git`, and point `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_SYSTEM` at the null device so fixtures are hermetic against host configuration; (b) add a fixture tripwire — immediately after a fixture `git init`, assert `git rev-parse --absolute-git-dir` resolves inside the fixture temp directory and throw loudly otherwise, converting any future leak into a test failure instead of silent corruption; (c) restructure hooks to the community-standard shape — pre-commit runs fast checks only (lint + typecheck); the full test suite moves to pre-push; and any hook that invokes the suite scrubs `GIT_*` from the environment first, because pre-push is also a git hook and receives the same repository-context environment; (d) annotate the 2026-08-03 journal workaround as retired once shipped — with fast commits and hermetic fixtures, routine `--no-verify` loses its justification. The env scrub closes the defect; the hook restructure removes the bypass incentive — a full-suite pre-commit is the recognized anti-pattern that bred this repository's documented `--no-verify` workaround culture, and per ARC-024 a routinely bypassed control is inert. CI (which already runs the full suite on every PR against a protected `main`) remains the authoritative gate throughout.

## Required tests

Negative regression per ARC-027 doctrine: point `GIT_DIR` at a decoy repository, run a fixture helper, and assert the decoy gained no commits, refs, or config changes while the fixture operated on its own temp directory. Acceptance proof: the full suite runs green from inside a linked worktree — the environment in which all three firings occurred.
