## Claim

Some spells resolve `{BUSINESS_ROOT}` while five canonical spells hardcode `ventures/`, so a supported alternate root silently disappears from common workflows.

## Verification

Confirmed. Dynamic resolution exists in [spell-bootstrap-business.prompt.md](../../../src/assets/.github/prompts/spell-bootstrap-business.prompt.md#L32-L36), [spell-present-arcane.prompt.md](../../../src/assets/.github/prompts/spell-present-arcane.prompt.md#L35-L44), and [spell-product-review.prompt.md](../../../src/assets/.github/prompts/spell-product-review.prompt.md#L22-L27). Literal `ventures/` remains in [spell-check-drift.prompt.md](../../../src/assets/.github/prompts/spell-check-drift.prompt.md#L30), [spell-commit-work.prompt.md](../../../src/assets/.github/prompts/spell-commit-work.prompt.md#L76-L80), [spell-open-session.prompt.md](../../../src/assets/.github/prompts/spell-open-session.prompt.md#L31), [spell-plan.prompt.md](../../../src/assets/.github/prompts/spell-plan.prompt.md#L67), and [spell-todo.prompt.md](../../../src/assets/.github/prompts/spell-todo.prompt.md#L48).

## Impact

Repositories using `businesses/`, `projects/`, or another declared root receive incomplete scans and misplaced TODO or planning behavior without an error.

## Proposed fix

Replace the five literals with one shared resolution rule. Land the canonical storage shape through EF-14 first, then use a documented default only when no configured or detected root exists.

## Open questions

Should root detection remain a fallback after a schema exists, or should missing configuration become a drift error?
