## Claim

Git for Windows can issue filesystem-retry prompts during an autonomous branch rename, blocking indefinitely because Arcane defines no non-interactive input or timeout policy for Git operations.

## Verification

The exposure is confirmed; the exact deadlock is not reproduced here. Arcane still prescribes the reported `git branch -m <old> <new>` sequence at [git-conventions.md](../../../src/assets/.arcane/governance/git-conventions.md#L214-L223), and `spell-open-session` requires noncompliant branch renames at [spell-open-session.prompt.md](../../../src/assets/.github/prompts/spell-open-session.prompt.md#L55-L62). The executable Git helper supplies only `cwd`, with no timeout, stdin, signal, or environment controls at [git.ts](../../../src/modules/git.ts#L6-L13).

Repository-wide canonical-source search found no `GIT_TERMINAL_PROMPT`, askpass policy, closed stdin, optional-lock setting, or Git timeout wrapper. However, the exact three retry prompts require a filesystem that refuses directory deletion and were not safely reproducible here. The batch's `spell-check-drift` example is stale: that prompt's Git scope describes tracked-document analysis but issues no Git command at [spell-check-drift.prompt.md](../../../src/assets/.github/prompts/spell-check-drift.prompt.md#L30-L40).

## Impact

An autonomous session can lose availability with no completion signal. Killing a blocked mutating operation can also leave refs or locks in an uncertain state.

## Proposed fix

Research the exact Git for Windows prompt under a deletion-restricted fixture. Test closed stdin, credential-prompt suppression, and command-class-specific timeouts independently. Then define one non-interactive, cancellable, bounded Git execution contract for prompts and TypeScript helpers.

## Open questions

Does stdin redirection fail closed or leave the rename partially completed? Which runtime hosts already detect prompts or impose deadlines, and what upper bounds are safe for large `add`, fetch, and push operations?
