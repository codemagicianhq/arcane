## Claim

Arcane recognizes docs-only repositories in governance but offers no docs profile or spell behavior that removes code, test, CI, and PRD assumptions.

## Verification

Confirmed in its corrected form. The profile union and profile table contain no docs option at [types.ts](../../../src/types.ts#L39) and [profiles.ts](../../../src/config/profiles.ts#L24-L67). The full profile installs all components, while lite still installs testing standards at [profiles.ts](../../../src/config/profiles.ts#L31-L37). However, the premise that Arcane never considered docs-only repositories is false: [cicd-standards.md](../../../src/assets/.arcane/governance/cicd-standards.md#L38-L52) explicitly defines a docs-only branch policy. The defect is the gap between governance and executable profile/spell behavior.

Coupling note: this profile decision is linked to tracker configuration in [EF-14](EF-14.md). "Docs/journal-style repository" versus "artifact-producing repository" and "internal tracker" versus "external tracker" are currently captured as separate prompts even though they mostly answer the same classification question.

## Impact

Docs repositories receive irrelevant gates and workflows, while the few docs-specific rules that do exist are not selected or enforced consistently.

Without [EF-14](EF-14.md), profile and tracker intent are asked separately and repeatedly, which increases operator error risk and produces inconsistent spell behavior across sessions.

## Proposed fix

Specify a docs profile as one coherent PRD covering component selection, Git lifecycle, document security, subject layout, adoption, and records conventions. Do not implement the related items as disconnected fields or templates.

Include reciprocal alignment with [EF-14](EF-14.md): profile selection and tracker mode should be captured as one coherent setup flow, persisted once, and reused by spells rather than asked as independent recurring questions.

The unified PRD covers EF-03, EF-04, EF-07, EF-10, EF-11, EF-12, EF-17, and EF-19. Its design may be written, reviewed, and accepted now, but implementation is explicitly queued behind the concrete shipped-code defects EF-25 through EF-29. EF-25 is the first execution priority: Arcane must stop destroying user-owned decision, backlog, and handoff history on update before adding a new profile. PRD acceptance does not authorize docs-mode implementation ahead of those fixes.

## Open questions

Which current spells are domain-agnostic after source review, and should mixed code/docs repositories use profile composition rather than a fifth fixed bundle?
