## Claim

`git-conventions.md` mandates rebase-and-fast-forward to preserve linear history and attribution trailers, but the maintainer's own Git environment defaults `pull.rebase` to `false`. A plain `git pull` on this machine creates a merge commit, directly contradicting the repository's own governance.

## Verification

Confirmed. `git config --show-origin --get pull.rebase` resolves to `false` from `C:/Program Files/Git/etc/gitconfig` — the Git for Windows system-level default, not a value this repository or Arcane ever sets. [`git-conventions.md`](../../../.arcane/governance/git-conventions.md#L318-L327) states rebase-and-fast-forward is the required strategy ("**Yes**... Preserves linear history while keeping individual commits and attribution trailers intact") and explicitly instructs `git rebase origin/main` before pushing. Nothing in `spell init`, `spell update`, or any spell sets a repository-local `pull.rebase` value to align the operator's default `git pull` behavior with that mandate.

This is the same shape as EF-31: a normative control (rebase-and-fast-forward, EF-24) is fully declared in governance prose but has no enforcement owner. Unlike EF-31 (a CI gate that exists but isn't wired), here there is no gate at all — the contract exists only as documentation the operator must remember to override manually, on every fresh clone or machine, against a hostile system default.

## Impact

Any session that runs a bare `git pull` instead of the documented fetch+rebase sequence silently produces a merge commit, breaking the linear-history invariant the repository's own ruleset and governance both require. Because the divergence is a system-level default rather than a per-repository setting, it recurs on every fresh clone, every new machine, and every contributor who has not manually configured `pull.rebase=true` — the exact class of drift EF-24 identifies as invisible until it fires.

## Proposed fix

Have `spell init` set a repository-local `git config pull.rebase true` (and optionally `git config rebase.autoStuff` equivalents already in use) as part of its Git-state checks, so the operator's own environment cannot silently default against the mandate. Add a `doctor`/init check that warns (not silently corrects) when the effective `pull.rebase` for the repository resolves to anything other than `true`, since correcting it without disclosure would itself be an undeclared side effect.

## Required tests

Add a regression fixture that creates a repository with `pull.rebase` unset (simulating the Git for Windows default), runs the relevant `spell init` step, and asserts the repository-local config now resolves `pull.rebase=true`. Add a second fixture proving an existing explicit `pull.rebase=false` set by the operator is surfaced as a warning rather than silently overwritten.
