## Claim

Arcane's CI templates either scope execution through `paths.include` or omit path filters, so new code locations can bypass CI while docs-only commits can still consume full pipelines. Commit-message metadata must not become the workaround.

## Verification

Confirmed, with another tier-B premise failure. The batch says all three code-pipeline templates carry path filters, but the Node.js template has none at [cicd-standards.md](../../../src/assets/.arcane/governance/cicd-standards.md#L97-L128). The .NET template uses `paths.include: src/**` at [cicd-standards.md](../../../src/assets/.arcane/governance/cicd-standards.md#L59-L74), and the Terraform PR template includes only `infrastructure/terraform/**` at [cicd-standards.md](../../../src/assets/.arcane/governance/cicd-standards.md#L131-L145). The Markdown pipeline also uses an include filter at [cicd-standards.md](../../../src/assets/.arcane/governance/cicd-standards.md#L160-L173).

No current source was found that skips CI by commit message, so that part is a proposed security prohibition rather than an existing exploit. No shipped guidance explains coordination between YAML triggers and independent branch-policy path filters.

## Impact

The Node template spends CI on docs-only changes. Include-only code paths can silently miss a newly introduced code or build-input directory, while mismatched branch policies can wait for a build that never queues.

## Proposed fix

Decide a fail-safe changed-path policy and test it for docs-only, code-only, mixed, new-directory, and pipeline-definition changes. Prefer narrowly excluding known inert document locations while ensuring pipeline files, manifests, lockfiles, scripts, migrations, and infrastructure always trigger. Add an explicit rule forbidding commit message, author, or branch naming as a CI trust signal, and document matching branch-policy configuration.

## Open questions

Which paths are actually inert across profile types, and should Arcane ship provider-specific branch-policy examples or limit itself to invariants and tests?
