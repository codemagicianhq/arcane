## Claim

Arcane emits no docs-oriented `.gitattributes` or `.gitignore`, leaving binary document handling, Office lock files, OS metadata, and sync-client artifacts to local defaults.

## Verification

Confirmed for emitted files. No component in the canonical registry at [registry.ts](../../../src/modules/registry.ts#L13-L182) installs `.gitattributes` or `.gitignore`, and no docs profile exists at [profiles.ts](../../../src/config/profiles.ts#L24-L67).

The blanket premise that Git necessarily treats every listed Office/image type as text does not reproduce as a source fact; Git's native binary heuristic often detects NUL-containing formats. The reliable defect is the absence of an explicit, portable repository policy and ignore rules.

## Impact

Behavior varies across Git installations. Lock files and platform debris can be staged, while diff and merge behavior for records remains implicit rather than reviewable.

## Proposed fix

Design and test a docs-profile `.gitattributes` and `.gitignore` pair. Mark supported binary formats explicitly, ignore transient Office/OS/sync files, and keep the line-ending baseline from EF-17 in the same template.

## Open questions

Which document formats are in the supported baseline, and should Git LFS recommendations be included for large or frequently changing binaries?
