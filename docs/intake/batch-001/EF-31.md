## Claim

Arcane has a complete distributable-version gate, exposes it as `check:version-bump`, and documents the rule, but CI never executes the gate. Changes to shipped assets can therefore merge without changing the package version.

## Verification

Confirmed. `scripts/check-version-bump.ts` watches `src/assets/`, `src/modules/registry.ts`, and `src/config/profiles.ts`; compares the PR head with `origin/main`; exits 1 when distributable content changed without a version bump; and passes when no distributable path changed. `package.json` exposes it as `check:version-bump`, and `CLAUDE.md` states the version-bump rule.

`.github/workflows/ci.yml` runs rebase-check, lint, type-check, build, and test. It never runs `npm run check:version-bump`, and the build job checkout does not request the full history/base ref the gate needs.

PRs #17 and #18 both changed `src/assets/.github/prompts/` while `package.json` remained at `0.14.0`, and both passed CI. The existing gate would have rejected both PRs. Because the package version never advanced, release-drift had no new input, no GitHub Release was created, `publish.yml` never ran, and npm remained stale.

This is the strongest EF-24 enforcement-contract failure found so far: the enforcement code was written, tested by hand, documented in `CLAUDE.md`, and then not connected to anything that executes.

## Impact

CI reports success for distributable changes that cannot be published. Every downstream release and publish mechanism can work correctly while receiving no version-change input, leaving npm and consuming repositories behind merged source.

## Proposed fix

Wire `npm run check:version-bump` into the required CI build job. Checkout full history and fetch the pull request base branch before invoking the gate so `origin/main` and the merge base are available.

Bump the package to `0.15.0` after the gate fix merges. This is a minor release because governance capability was added and `spell update` now refuses dirty, non-Git, and unborn repositories.

## Required tests

Add a negative integration fixture that creates a PR-shaped Git history, changes a file under `src/assets/` without changing `package.json`, executes the real gate, and asserts a nonzero exit with the missing-version-bump message. A green test that only exercises the no-distributable-change path is insufficient.

Also retain a non-distributable control fixture proving unrelated changes still pass without a bump.
