## Claim

Arcane focuses on credentials and PII leakage but does not tell agents to reference sensitive records without transcribing them into journals, decisions, screenshots, or other framework-layer documents.

## Verification

Confirmed. `spell-close-session` asks agents to retain durable screenshots and delete those containing secrets, tokens, or PII at [spell-close-session.prompt.md](../../../src/assets/.github/prompts/spell-close-session.prompt.md#L91-L98). The universal rule uses the same screenshot framing at [universal-agent-rules.md](../../../src/assets/.arcane/governance/universal-agent-rules.md#L62-L71). Neither source defines a records-mode default against transcription or screenshot retention when the underlying subject matter is itself sensitive.

## Impact

Agents can duplicate protected content into more widely read Arcane metadata. In a records repository, screenshots are sensitive by default rather than exceptional.

## Proposed fix

For sensitive/docs mode, default to path references without content transcription and no screenshot retention unless explicitly justified. Add redaction and least-copy principles to the profile's governance, with enforcement scoped to the Arcane metadata layer.

## Open questions

How is a repository declared sensitive, and which sanitized summaries remain permissible when raw contents cannot cross into journals or decisions?
