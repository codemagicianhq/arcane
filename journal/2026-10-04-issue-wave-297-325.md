### Lessons Learned

#### A rule's home is decided by the target doc's own stated scope, not by where similar rules live

The approved plan put #298's OTA/native rule into `mobile-release-standards.md` as `MR-15`. That doc's
introduction limits it to platform behaviour that holds regardless of build tool, and the OTA rule is
expo-updates behaviour. Reading the doc's scope statement before writing caught this. The rule went
into `spell-eas-store-deploy` instead, and the PR recorded the correction.

#### Probe a destructive claim before writing a warning about it

Issue #323 reported `git worktree remove --force` following a Windows junction. A two-minute Linux
probe (git 2.43.0) showed a symlink is *not* followed. Without it, the warning would have overstated
the hazard on every platform. The warning now separates "observed once" from "tested".

#### An adversarial review by a fresh-context reviewer found what self-checking missed

Every gate was green before review. A reviewer with no session context still found real defects:
- a post-merge check that no step ever ran (R1);
- a PowerShell listing that, on 5.1, would walk into the very junction it guards (R4);
- a handoff mechanism that would auto-run commands from an editable file (R6).

A green suite proved the text was present, not that it was right.

#### This runtime withholds model identifiers, but the repo requires a `Model:` trailer

Commits used `Model: withheld`. Trailers are advisory under ARC-023, so nothing failed. But the
attribution standard has no defined value for a runtime that may not disclose its model.

### Lessons Learned

#### A closed issue is not proof its change shipped

#332 showed `closed`, and GitHub linked the closure to #334. That PR only changed #332's marker in
`FEEDBACK.md`; the requested change to `spell-feedback.md` was not there. Checking the spell text,
not the issue state, caught it. `spell-close-session` step 10 confirms each issue is closed after a
merge; it does not confirm the merged diff contains the change the issue asked for.

#### A filing flow that never clears its own queue invites duplicates

`spell-feedback --flush` filed items but never changed their `queued` marker, so every later flush
would offer them again. #334 fixed the markers by hand, and #335 put the step into the spell.
