### Lessons Learned

#### A suite that keeps slowing down is an environment problem until shown otherwise

The pre-push suite went from about 100 s to 140 s, 161 s and then 610 s over 2026-10-20 and
2026-10-21. The hook refused the wave branch on tests timing out at 5 s that the wave never touched. I
first treated the timeouts as flakiness and asked for `--no-verify`. CPU load and the node processes
looked normal, so the early checks found nothing. Two causes surfaced later. Tests that never removed
what `createFixtureDir` made had leaked 72,000 directories into `%TEMP%` since 2026-09-03, and a
`git grep` from another session's shell had been running for an hour. Vitest's default of 15 workers
on this machine added the rest, and PR #384 capped it at 4. When a suite slows run after run, count the
`%TEMP%` entries and look for long-lived `git.exe` processes before touching the code or the hook.
Routed to `FEEDBACK.md`? No: repo-local, and the fixes are PRs #383 and #384.

#### CI has no user tier

Two existing tests updated a `spell_scope: "user"` repository and passed here only because this
machine has `~/.arcane`. The #359 refusal made them fail on Ubuntu after the local suite had passed.
Running the affected suites with `HOME` and `USERPROFILE` pointed at an empty directory reproduced CI
in seconds. `test/helpers/user-tier-home.ts` now gives such tests a tier of their own. Routed to
`FEEDBACK.md`? No: repo-local.

#### A platform-only branch cannot meet a per-file coverage threshold on a one-OS CI job

The Windows-only `rmdir` fallback could never run on Ubuntu, so `copier.ts` fell to 94.33% branches
against its 95% threshold, a failure no local Windows run would show. The fallback was dead on Windows
as well. The review had flagged it (F6), and I narrowed it instead of removing it, which cost a CI
round. Routed to `FEEDBACK.md`? No: repo-local.

#### Concurrent closes rewrite one handoff block

Five sessions closed on 2026-10-21, and each `spell-close-session` run replaced the single
`## Next Session Handoff` block. Nothing in the spell orders concurrent closes or merges their items.
The parent session had to be sequenced last by hand, and each close carried the others' open items
forward by reading the block on `main` first. One session even sent a correction to an earlier close
for this one to apply; the cap-vitest close had already made it. Routed to `FEEDBACK.md` (queued for
upstream).

#### My errors, named

I wrote into `TODO.md` that the symlink tests had never run on Windows, while the pre-push hook had
just run them; PR #378 corrected it. I first wrote handler tests that each ran a full `spell init`,
76 s for one file, adding load to a suite that was already timing out. A shell heredoc halved a
backslash in a regex, so `/\\/g` became `/\/g`; lint caught it, and the memory note on heredocs had
already warned about exactly this. Routed to `FEEDBACK.md`? No: repo-local.
